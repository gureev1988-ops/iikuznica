## План пилота в Тех.разделе

- [ ] Перенести итоговый согласованный текст в `docs/pilot-softline.md`. README в `main` уже ссылается на этот файл. [Текущая согласованная редакция](../pilot-softline.md) служит основой для ожидаемых правок текста.
- [ ] Вывести полный план первым блоком «Тех.раздела» и первым пунктом меню с якорем `#tech-pilot`. После него разместить шесть технических блоков в прежнем порядке. [ТЗ первого экрана](softline-pilot-section.md).
- [ ] Обновить приёмку экрана и браузерный тест, который сейчас ожидает шесть блоков. На широком и узком экранах при открытии вкладки видно начало плана. Первый пункт меню ведёт к плану, текст совпадает с итоговой редакцией в Git. [Текущий тест](https://github.com/gureev1988-ops/iikuznica/blob/42e173d66242edcb7962e79b9e4fc820a9653655/tests/browser/test_assembly.py#L389).

## Новый вопрос при открытом уточнении в DION

- [ ] В сетевом адаптере отделить короткий самостоятельный вопрос от выбора варианта. При одном открытом уточнении «Срок реализации проекта» сейчас может засчитаться как выбор «Реализация проекта». Самостоятельный вопрос должен открыть новое дело, старое уточнение остаётся доступным.
- [ ] Проверить на тестовом транспорте DION обе траектории. «Срок реализации проекта» идёт как новый вопрос. Номер, «Реализация» и «Уже реализуем проект» продолжают исходное уточнение, когда в списке есть соответствующий вариант. [ТЗ уточнений](../architecture/dion-numbered-clarifications.md#как-бот-разбирает-ответ) · [Маршрутизация в адаптере](https://github.com/gureev1988-ops/iikuznica/blob/42e173d66242edcb7962e79b9e4fc820a9653655/backend/dion/adapter.py#L356).
