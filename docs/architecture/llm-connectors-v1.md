# Переключение ИИкузницы на локальные модели

Публичный демостенд использует OpenRouter. Для пилота в Git подготовлен профиль `II_MODEL_PROFILE=local`. Оператор задаёт полный адрес, идентификатор модели и при необходимости Bearer-токен для каждой из трёх ролей. Эту конфигурацию получают API, интерактивный и фоновый воркеры, а также процесс инициализации.

| Роль | Что отправляет приложение | Что проверяется в ответе |
| --- | --- | --- |
| Gemma | Сообщения чата, включая запросы поиска, почты и сверки FAQ, на `/v1/chat/completions` | Непустой ответ в потоке SSE, нормальное завершение и событие `[DONE]` |
| Qwen | Запросы полных процедур на отдельную точку `/v1/chat/completions` | Тот же потоковый контракт. Режим рассуждения задаётся в конфигурации сервера |
| Decider | Состояние и именованные вопросы на `/v1/decisions` | Для каждого вопроса возвращается решение его типа. Для `choice` требуются допустимый вариант, уверенность и вероятность каждого варианта. Для `noul` требуется число от 0 до 1. Сервис использует нативную модель Decider |

В локальном профиле повтор модельного вызова идёт на тот же внутренний адрес. Приложение обходит HTTP-прокси окружения, отклоняет перенаправления и проверяет идентификатор модели, когда сервис его сообщает. MiniLM загружается с диска после сверки контрольных сумм. Доступ к разрешённым адресам и источникам пакетов при развёртывании настраивает ИТ в сети пилота.

## Как проверить подготовку

1. На GPU-узле подготовьте образы и веса закреплённых версий и запустите Gemma, Qwen и Decider по [инструкции для модельных сервисов](../../deploy/local-inference/README.md).
2. На узле приложения заполните [пример конфигурации](../../deploy/models/local.env.example) и подключите [локальный профиль Compose](../../deploy/models/compose.local.yaml). В [инструкции оператора](../backend/local-models.md) даны команды подготовки MiniLM, проверки, переключения и отката.
3. До открытия доступа пользователям выполните `python -m backend.assembly.check_models` внутри контейнера приложения. Проверка посылает каждой роли синтетический запрос, показывает адрес и идентификаторы и завершается с ошибкой при отказе. Режим `--config-only` проверяет только параметры.

Автотесты используют тестовые HTTP-сервисы. Они проверяют переключение ролей, потоковый и нативный протоколы, обработку отказа, фоновую сверку FAQ с PostgreSQL и возврат ответа эксперта в чат через тестовый почтовый ящик. На оборудовании Softline предстоит запустить закреплённые веса, проверить ответы и ссылки на контрольных вопросах, пройти почтовый цикл и измерить задержки и пиковую память при согласованной нагрузке.
