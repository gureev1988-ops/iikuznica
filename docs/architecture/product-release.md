# Как проверить демостенд

«Демо чат DION» отвечает по четырём учебным регламентам. По ссылке у ответа можно проверить цитату, открыть названную редакцию или скачать оригинал. Для показа достаточно браузера. [Открыть стенд](https://corpdoc.single-tech.ru/)

## Что проверить в браузере

| Действие | Ожидаемый результат |
| --- | --- |
| Спросите «На инициации проекта дирекции ИБ, если все входные данные уже переданы, кто выделяет руководителя проекта и какой у него срок?» | Координатор департамента назначает РП в течение одного рабочего дня. Ссылка открывает п. 2.7 регламента «Проектная деятельность Дирекции ИБ». |
| Задайте отдельно вопрос «За сколько мне назначат руководителя проекта?». Ответьте на уточнение «Это проект ДБРЦТ, он уже на инициации». | Бот учитывает указанную дирекцию и ссылается на п. 7.2 регламента ДБРЦТ. На нумерованное уточнение также можно ответить цифрой. |
| В «Отделе качества» откройте разъяснение ОК1 о точной оценке в ДБРЦТ. Сравните письмо с п. 1.6 второй учебной редакции. | В письме указан срок 6 рабочих дней, в действующем регламенте — 7. Инструкцию определяет действующий регламент. В первой редакции того же пункта можно проверить прежний срок в 5 рабочих дней. |

Когда два действующих регламента дают несовместимые указания для одной роли, дирекции и этапа, бот показывает оба пункта и предлагает передать вопрос в Отдел качества. Письмо уходит после согласия сотрудника.

### Как проверить ответ эксперта

1. В чате спросите о минимальной маржинальности на пресейле ИБ для вымышленного проекта. Добавьте своё обозначение проекта, чтобы потом найти письмо. В учебном корпусе нет профильного регламента, и бот предложит обратиться в Отдел качества.
2. Подтвердите отправку в чате. В «Отделе качества» откройте «Входящие письма» и найдите свою цепочку по обозначению проекта.
3. Войдите как эксперт и ответьте в этой цепочке. Укажите, что названное значение относится только к вашему учебному проекту. Ящик и карточки разъяснений общие для участников стенда.
4. Вернитесь в исходный чат. Ответ эксперта приходит туда же, даже если вкладку закрывали. Итоговое разъяснение становится доступно для следующих вопросов с теми же условиями. У каждого браузерного профиля своя история чата.

Эти сценарии можно повторить на локальной сборке. [Браузерные тесты](../../tests/browser/test_assembly.py) · [Команды приёмки](../backend/assembly-run.md)

## Устройство стенда

| Компонент | Роль в профиле `assembly` |
| --- | --- |
| Caddy и FastAPI | Принимают запросы по HTTPS, отдают интерфейс, историю чата и ссылки на документы. |
| PostgreSQL и воркер чата | Хранят диалоги и очередь. Для поиска A1 подбирает пункты среди доступных сотруднику документов, а MiniLM ранжирует кандидатов на CPU. |
| Модели | Для вопросов, требующих модельной обработки, используются Gemma, Qwen и Decider через OpenRouter. В «Логах» чата можно открыть запись последнего хода. |
| Фоновый воркер и учебная почта | Воркер отправляет обращения по SMTP и получает ответы по IMAP. Итоговый ответ из доверенного ящика связывается с исходным обращением. |

На старте сборка импортирует DOCX из репозитория. В корпоративном контуре предусмотрены адаптеры DION Bot API и Confluence, а также импорт полных каталогов HTTPS/JSON. Условия подключения и этапы проверки приведены отдельно. ## Что показали измерения

27 ноября 2026 года на локальной сборке поверх `106608c` проверили три заранее известных вопроса. Во всех трёх ответах проверяющие открыли нужные пункты и сверили цитаты с сохранёнными редакциями. Суммарный зарегистрированный расход модельных вызовов составил $0,00120126. Размер и состав выборки ограничивают выводы о качестве на других вопросах.

В отдельном нагрузочном прогоне образа `f156a9e1` через OpenRouter все 10 одновременных запросов завершились. Восемь ответов содержали цитаты, два запросили уточнение. Время до полезной реплики составило 5,591 с по медиане и 7,399 с по p95. Повторить измерение на конкретном выпуске можно по инструкции приёмки.
