# Приоритет утверждённого регламента и проверка FAQ из почты

Действует по подтверждению заказчика от 27 ноября 2026 года, 13:02 МСК. Регламент является утверждённым документом. Отдел качества объясняет, как применять его в конкретной ситуации. Для сотрудника действующая применимая норма определяет инструкцию. Этот порядок заменяет ранее записанный приоритет FAQ при конфликте.

## Ответ сотруднику

1. Проверяем действующую редакцию, область применения и доступ к обоим источникам. Сравниваем только выводы для одной операции и одинаковых условий.
2. При наличии применимых регламента и FAQ показываем оба с раздельными ссылками. При совпадении достаточно одного вывода с двумя подписанными источниками. При расхождении указываем, какой вывод следует из регламента, и отдельно приводим позицию FAQ. Предлагаем повторно уточнить расхождение письмом. Письмо уходит только после согласия сотрудника.
3. Когда регламент оставляет пробел, применимое подтверждённое разъяснение может дополнить ответ в пределах подтверждённых условий. Показываем его как консультацию. Если применимые регламенты действительно расходятся и формального основания выбрать один нет, показываем оба и предлагаем уточнение. FAQ может пояснить область действия.
4. Те же правила действуют для исходной переписки после ответа по почте, следующих вопросов, веба и DION. Сырые письма и данные обращения доступны по прежним правилам доступа. Ссылка на FAQ другим сотрудникам ведёт на разрешённую выдержку.

Пример для одинаковых условий. **Регламент** — 7 рабочих дней, ссылка на действующую редакцию и пункт. **FAQ Отдела качества** — 2 рабочих дня, ссылка на разъяснение. Руководствуйтесь сроком 7 рабочих дней по регламенту. Повторно уточнить расхождение письмом?

## Проверка и работа Отдела качества

- Содержательный ответ из доверенного ящика на распознанное обращение сразу возвращается в чат и автоматически попадает в FAQ. Первичная проверка запускается при каждом добавлении и изменении FAQ. Ручное согласование перед публикацией не требуется.
- По рабочему вопросу и условиям подбираем применимые пункты действующей редакции. Сопоставляем смысл, включая роль, действие, срок, единицу, условие и исключение. При расхождении или обоснованной неопределённости со связанным кандидатом ставим **«Возможное противоречие»**. При незавершённой проверке храним её состояние отдельно. Отсутствие найденного пункта само по себе не является конфликтом.
- Действующий регламент определяет инструкцию с первого ответа, в том числе пока проверка FAQ не завершилась. Неопределённость разрешается уточнением либо адресным предложением обратиться в Отдел качества.
- В очереди разборов показываем разрешённую выдержку FAQ, исходное письмо уполномоченному модератору, применимый пункт и редакцию регламента. Действия модератора — **«Редактировать»** и **«Отозвать»**. Правка создаёт новую версию и повторную проверку. Отзыв исключает FAQ из следующих ответов. Историю письма и ранее показанных реплик сохраняем.
- Публикация новой редакции повторно проверяет связанные FAQ. Повтор доставки письма или синхронизации с теми же версиями не создаёт новый FAQ и не дублирует задачу. Отозванная запись не возвращается при повторе. Права и область проверяются перед показом каждого источника.

## Что меняется в бэкенде

На контрольной ревизии `19e9ce0` `DialogueService.answer_job` позволяет завершить ход по совпавшему FAQ до поиска по регламенту. Та же логика применяется при завершении хода и повторной проверке доставки в DION. Для нового правила выдача сначала устанавливает нормативное основание и только затем добавляет применимый FAQ. Ответ с подтверждённой нормой сохраняет тип `answer` и может предложить перевод в почтовое уточнение через существующий маршрут согласия. [Текущий путь диалога](../../backend/dialog/service.py)

Почтовый путь уже публикует FAQ и хранит идентификатор возможного конфликта для сопоставленных документов. API Отдела качества уже поддерживает замену и отзыв. Сейчас проверка при публикации зависит от существующей связи или совпадения заголовка. Обязательная проверка охватывает каждую новую или изменённую запись и использует смысл и область применимости. Обновляем также сообщение, которое приходит в исходный чат из почты. ## Приёмка

| Сценарий | Ожидаемый результат |
|---|---|
| FAQ из письма указывает 2 дня, действующий регламент — 7 | И в исходном, и в повторном чате 7 по регламенту. Отдельно показаны 2 из FAQ, две ссылки и предложение повторно уточнить. В Отделе качества есть «Возможное противоречие». |
| FAQ и действующий пункт согласуются | Один вывод и два источника, без пометки о конфликте. |
| FAQ и пункт сходятся по словам, но действуют в разных условиях | Показывается применимый источник. Сопоставление разных областей не создаёт ложного конфликта. |
| Регламент меняет срок с 2 на 7 | Новая редакция действует с первого ответа. Связанный FAQ переходит на проверку, старые ссылки сохраняются в истории. |
| Модератор исправляет 2 на 7 или отзывает запись | После правки доступны согласованные источники. После отзыва остаётся регламент. Повторная доставка и синхронизация не восстанавливают FAQ. |
| В регламенте нет нормы для запрошенного реквизита | Подтверждённый FAQ виден как консультация в своей области. При отсутствии обоих оснований предлагается адресное уточнение. |

Для обеих финальных конфигураций поискового ядра правило приоритета и эта проверка едины. Ошибочная инструкция по FAQ, противоречащему регламенту, считается критической. Ранее сохранённые результаты экспериментов относятся к их зафиксированным конфигурациям.
