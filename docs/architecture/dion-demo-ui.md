# Демо чат DION · подсказки и логи

Согласовано 27 ноября 2026 года. [Интерактивный макет](https://chatgpt.com/library?file_id=libfile_77f91857fd488191b8f059b71557c477&no_universal_links=1).

Схемы маршрутизации, разъяснений, развёртывания и модельные профили описаны в [Тех.разделе](dion-tech-section.md).

## Подсказки

Под шапкой «Регламент бот», над сообщениями, показываем одну компактную плашку в цветах DION. Слева «Подсказка:», действие и текст примера. Справа «Применить». Кнопка подставляет пример в поле ввода и фокусирует его. Отправка происходит по Enter или кнопке «Отправить». Shift+Enter вставляет новую строку. Enter при активном составном вводе (IME) завершает ввод символа.

Подсказки сопровождают три сценария заказчика: ответ с точной ссылкой, уточняющий диалог и передача пробела в Отдел качества с повторным использованием разъяснения. Составной вопрос показывает работу с несколькими частями запроса.

| Этап | Текст и действие | Когда сменить подсказку |
| --- | --- | --- |
| Простой вопрос | «Начните с простого вопроса и откройте пункт регламента». «Применить» подставляет проверенный вопрос с однозначным ответом. | В чате появился ответ с применимой ссылкой, и сотрудник открыл пункт. После ответа можно оставить короткую подсказку открыть пункт. |
| Составной вопрос | «Попробуйте составной вопрос». Пример содержит несколько связанных частей с отдельными основаниями. | Бот вернул результат по всем частям с применимыми источниками. |
| Уточнение | «Задайте вопрос без указания дирекции». Когда бот задаёт уточнение, текст меняется на «Ответьте на уточнение бота». Пример продолжения соответствует запрошенному факту. | После уточнения получен прямой ответ с источником. |
| Профильный пробел | «Попробуйте вопрос, на который в регламентах нет ответа». Пример относится к рабочему процессу, для него отсутствует достаточное основание в текущих регламентах и FAQ. | Бот предложил отправить обращение. |
| Согласие | «Подтвердите отправку обращения в Отдел качества». «Применить» подставляет «Да, передай». | Сотрудник подтвердил отправку. При отказе письма нет, подсказка возвращается к выбору вопроса с пробелом. |
| Ответ Отдела качества | «Ответьте на письмо в разделе „Отдел качества“. После этого ответ появится здесь». «Открыть входящие» открывает нужную цепочку без входа. | Ответ из доверенной почтовой цепочки доставлен в исходный диалог и разъяснение доступно для повторного запроса. |
| Повтор | «Задайте вопрос ещё раз, чтобы проверить новое разъяснение». Пример — исходный вопрос. | Бот ответил по применимому разъяснению. Плашка скрывается. |

Храним текущий шаг, выбранный пример и связанное обращение в пределах личной сессии DION. Случайный выбор делаем внутри категории один раз на шаг. Ввод, перерисовка, переход на вкладку почты и возврат не перебирают примеры. Вопрос можно сформулировать вручную. Смена шагов опирается на фактические результаты диалога и события, включая открытие источника и состояние обращения. Связанный ответ должен переключать подсказку только в чате владельца.

В публичный банк подсказок попадают только случаи из тестового корпуса с полным зачётом на сборке для показа. Для ответа проверяем все существенные части, условия и источники. Для уточнения и пробела проверяем также ожидаемое действие бота. Для почтового кейса проверяем цепочку до повторного ответа по разъяснению. При смене сборки, документов или базы FAQ перепроверяем применимость. Если для пробела уже есть подходящее разъяснение, выбираем другой зачтённый случай. Если пул пуст, пропускаем подсказку к отправке. Закрытый банк приёмки хранится отдельно. Интерактивный HTML показывает сценарии и демонстрационные события. Его ответы и расходы не являются результатом приёмки стенда.

## Логи последнего запроса

Кнопка «Логи» размещается слева внизу DION вместо «Как пользоваться». Панель открывается рядом с кнопкой. Показываем только последний ход пользователя в текущем авторизованном чате. До первого вопроса — пустое состояние. При новой отправке отображаем состояние её обработки и затем её журнал. Фоновые задачи и события других диалогов сюда не входят.

В очередности выполнения отображаем локальный поиск A1/MiniLM, маршрутизацию и судью, фактическую генерацию Gemma, Qwen или другой моделью и дополнительные вызовы, если они состоялись. Для каждого вызова показываем роль, модель, входные и выходные токены и стоимость в рублях. Повторы и резервные модели учитываем отдельными строками. Локальный шаг отмечаем как «локально». Его затраты на инфраструктуру не входят в стоимость API.

Для read-модели журнала берём события обработки и попытки запроса из серверного журнала. Привязки включают авторизованный чат, ход пользователя и trace ID. Для попытки нужны порядковый номер, роль, фактическая модель, провайдер, токены, статус и стоимость. Из OpenRouter берём стоимость каждого вызова из usage. При наличии только токенов считаем по действовавшим ставкам конкретной модели и провайдера за вход и выход, включая отдельную ставку кеша, если она применялась. В обоих случаях показываем сумму одним форматом. При недостаточных данных ставим «—» и показываем, что итог неполный. Ноль означает подтверждённый нулевой расход. Итог — сумма токенов и сумма стоимости вызовов в долларах × 85 ₽, с округлением только при показе. [Учёт использования OpenRouter](https://openrouter.ai/docs/quickstart) · [Тарифы](https://openrouter.ai/pricing).

### Исходящее письмо

Согласие пользователя может создать асинхронное действие. Привязываем почтовое событие к ходу, на котором получено согласие, и к номеру обращения. «Письмо отправлено» показываем после успешной передачи письма почтовому серверу. Пока задача в очереди или после ошибки показываем её фактический статус. Одно успешно отправленное письмо даёт одну запись, повтор доставки или обновление экрана её не дублирует.

В записи показываем номер обращения и поля «От» (бот), «Кому» (Отдел качества), «Копия» (сотрудник). Адреса берём из отправленного письма. На демостенде сотруднику назначаем стабильный тестовый адрес для его сессии в подконтрольном почтовом домене. В HTML достаточно демонстрационного адреса на `demo.example`. Журнал запроса виден только владельцу чата. Само учебное письмо и его тестовые адреса видны участникам в общем демонстрационном ящике. Текст письма, модельные промпты и секреты в этот экран не выводим. При отправке без модельного вызова журнал содержит почтовое событие и нулевой расход API.

## Права и начальные данные

Список, поиск и полный текст учебных цепочек, сохранённая переписка, разъяснения, источники и запуск проверки конфликтов доступны без входа. Автоматическая сверка меняет отметку проверки и публикует отчёт. Вход нужен для ответа на письмо, ручной правки, отмены и возобновления карточки. Сервер проверяет право на запись, интерфейс открывает вход при выборе соответствующего действия. «Ответить» показывается только у обращения без ответа Отдела качества. Повторный ответ на уже закрытое обращение отклоняется. Изменение опубликованного ответа проводят через карточку. Ссылку «Открыть разъяснение» из письма убираем.

На чистой базе боевого демостенда один раз создаём одну учебную завершённую цепочку с одним вопросом бота и ответом Отдела качества с тестовым адресом в копии. Вопрос: «Какой срок для выдачи точной оценки в ДБРЦТ?». Ответ письма: «Рекомендуемый срок выдачи точной оценки — 6 рабочих дней». Привязываем одну карточку «Действует», оставляем отметку проверки пустой. Действующий регламент «Проектная деятельность ДБРЦТ», п. 1.6, содержит срок 7 рабочих дней. Первое ручное нажатие «Проверить конфликты» выявляет расхождение и создаёт отчёт. Общий ящик содержит учебные письма. Стартовая цепочка не привязана к личному диалогу. Каждый новый личный DION открывается с пустой перепиской и стартовой подсказкой.

Проверяем случай с гостем: он читает исходное письмо, ищет по ответу, открывает переписку из карточки и проверяет конфликт. Вход открывается при выборе правки или ответа на новое обращение. У стартового и служебного писем нет действия «Ответить».

## Приёмка

1. Открыть чистый DION. Плашка видна над перепиской, журнал последнего запроса пуст. «Применить» заполняет черновик без отправки. Shift+Enter добавляет перенос, Enter отправляет ровно одну реплику. Повторить при композиционном вводе.
2. Пройти подсказки и один случай собственными словами. Простой ответ ведёт к точному пункту. Составной ответ покрывает все части. Уточнение и ответ меняют плашку по событиям. Случайный пример не скачет при повторном рендере.
3. Отказаться от первого предложения письма и подтвердить следующее. Проверить одну отправку, фактические поля From/To/Cc и привязку к ходу согласия. При сбое записи «Письмо отправлено» нет. Ответ приходит в тот же чат, повторный вопрос использует применимое разъяснение.
4. Сверить последнюю реплику с серверными попытками и вручную пересчитать итог по курсу 85. Проверить составной вызов, повтор, локальный этап, бесплатную модель и пропущенные данные. После нового сообщения журнал старой реплики исчезает. Другой гостевой браузер не видит личный чат и журнал первого. В общем демонстрационном ящике доступны только предусмотренные для показа тестовые письма.
