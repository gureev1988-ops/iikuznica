# ТЗ. Текстовый выбор варианта в Демо DION и DION

В уточнениях с готовыми вариантами бот пишет список в сообщении. Сотрудник выбирает вариант, отправив его номер через обычное поле ввода. Правило распространяется на все такие уточнения, в том числе про этап, подразделение или роль сотрудника.

## Сообщение бота

Бот показывает вопрос, затем варианты по одному на строке с номерами от 1. Под списком он пишет «Можете ответить просто цифрой.» Для каждого уточнения список начинается с 1. Порядок вариантов фиксируется на момент отправки и сохраняется в истории. Вариант «Не знаю», если он предусмотрен, получает номер в том же списке. Уточнение со свободным ответом выводится без списка и подсказки про цифру.

```text
На каком этапе находится работа по вашему запросу?

1. Пресейл (подготовка предложения)
2. Реализация проекта
3. Управление рисками
4. Запрос на новую услугу
5. Не знаю

Можете ответить просто цифрой.
```

## Как бот разбирает ответ

1. Если ответ целиком состоит из цифр после удаления пробелов по краям, бот сопоставляет число с позицией в показанном списке. Для `2` он применяет условия варианта «Реализация проекта» к исходному вопросу и продолжает поиск. Сопоставление выполняется до смыслового разбора текста. Цифры внутри обычной фразы, например «Мы уже 2 недели на реализации», проходят вместе с остальным текстом.
2. Демо DION привязывает ответ к открытому уточнению выбранного обращения. В DION ответ на конкретное сообщение привязывается к его списку. Отдельное сообщение с цифрой срабатывает, когда в этом диалоге есть ровно одно открытое уточнение с уже отправленным списком. Если таких списков несколько, бот просит ответить на нужное сообщение. Бот принимает ответ только для открытой версии именно этого списка. При закрытии или изменении списка он просит ответить на актуальное уточнение, если оно есть.
3. Если номера нет в актуальном списке, бот сообщает «Выберите номер от 1 до 5.» с фактической верхней границей и повторяет список. Уточнение остаётся открытым. Если в новом диалоге нет списка и сотрудник отправил только цифру, бот просит написать вопрос словами. Число в ответе на открытое уточнение без вариантов принимается как обычный текст.
4. Свободный текст, отправленный как ответ на уточнение, по-прежнему разбирается по смыслу. `5` из примера и «Не знаю» означают, что сотрудник не знает именно этап. Для другого уточнения это может быть роль, подразделение или другое условие. Продолжение определяется правилами смыслового роутинга для соответствующего условия.
5. В истории остаётся то, что сотрудник отправил, например `2`. Для поиска сохраняется расшифрованное условие «Реализация проекта». Если диалог переходит в письмо в Отдел качества, в переписке виден вопрос бота со списком и исходный ответ сотрудника, а в сводке условий указан выбранный вариант.

## Точки доработки

- Демо DION сейчас рисует кнопки из `clarification.options`. Вывести варианты в тексте сообщения и использовать существующую отправку `text` с `case_id`, `clarification_id` и `clarification_version`. [Код Демо DION](../../backend/assembly/frontend/app.js#L147)
- Адаптер DION уже нумерует варианты и разбирает цифру при ответе на сообщение или через `/answer`. Добавить привязку отдельно отправленной цифры к единственному открытому списку и использовать общий с демо разбор выбора. Номер должен разрешаться в существующий `option_id` по порядку реально показанных вариантов. Сохранить проверку актуальности уточнения и обработку повторной доставки сообщения. [Адаптер DION](../../backend/dion/adapter.py#L331) · [Обработка уточнения](../../backend/dialog/service.py#L288)

## Приёмка

| Действие | Ожидаемый результат |
|---|---|
| Бот уточняет этап | В сообщении пять пронумерованных строк и подсказка «Можете ответить просто цифрой.». Выбор доступен через поле ввода. |
| Сотрудник отдельным сообщением вводит `2` при одном открытом списке | Продолжается то же обращение с условием «Реализация проекта». В диалоге видно `2`. |
| Сотрудник пишет `5`, «Не знаю» или «Мы уже 2 недели на реализации» | Первые два ответа дают неизвестный этап. Последний проходит смысловой разбор и уточняет этап «Реализация проекта». |
| Сотрудник вводит `7` в примере | Бот повторяет список, уточнение остаётся открытым. |
| В DION открыто два списка или сотрудник отвечает на закрытое уточнение | Бот просит указать актуальное сообщение, состояние других обращений сохраняется. |
| Обращение передаётся в Отдел качества после ответа `2` | В диалоге письма есть показанный список и ответ `2`, в условиях обращения указан выбранный этап. |

Проверить на браузерном сценарии Демо DION и на тестовом провайдере адаптера. [Браузерные сценарии](../../tests/browser/test_assembly.py) · [Тест адаптера](../../tests/backend/test_dion.py#L345)
