## 1. Аналитика для Отдела качества

**Результат для пользователя.** В «Отделе качества» видны регламенты, которые чаще всего нужны сотрудникам, и пункты, где бот сталкивается с пробелом или подтверждённым расхождением. Для каждого пункта можно открыть редакцию, на которой основано наблюдение. Подраздел «Статистика» сохраняет эти показатели и добавляет повторяющиеся вопросы без ответа и оценки ответов. На демостенде гость видит агрегаты и доступные ссылки на регламенты. Для раскрытия исходных формулировок вопросов нужен вход в Отдел качества.

| Список | Что показываем | Как считаем |
| --- | --- | --- |
| Востребованные регламенты | Название, число выдач за период, ссылка на действующую редакцию. Сортировка по числу выдач. | Одна выдача на регламент в завершённом ходе, если документ процитирован в ответе или выдан как найденный регламент. Несколько цитат одного регламента в ходе дают одну выдачу. Два разных регламента в одном ответе дают по выдаче каждому. |
| Проблемные пункты | Регламент, редакция, номер или заголовок пункта, отдельные числа пробелов и подтверждённых расхождений FAQ. Ссылка открывает именно эту редакцию на пункте. | Пробелы — уникальные завершённые ходы за период с профильным вопросом без полного ответа и проверенной связью нерешённой части с пунктом. Расхождения — уникальные действующие или требующие пересмотра карточки с подтверждённым конфликтом с этим пунктом по последней проверке. Порядок — сначала по числу пробелов, затем по числу расхождений. |

- Для выдач и пробелов берём последние 30 календарных дней, включая сегодня, по МСК. Возле расхождений указываем «По последней проверке». У снятого расхождения и отменённой карточки вклад в текущий счётчик исчезает. Повторная проверка той же карточки сохраняет один конфликт. Статус проверки без подтверждённого конфликта в счётчик не входит.
- Ход без установленной связи с пунктом попадает в строку «Без привязки к пункту». В составном вопросе цитата к подтверждённой части не связывается с пробелом в другой части автоматически. Кандидаты поиска, промежуточные варианты уточнения, непрофильные вопросы и технические ошибки счётчики не меняют.
- Различаем выдачу регламента и его открытие. Для первого выпуска измеряем выдачи. Обновление страницы, повтор команды и повтор фоновой задачи числа не меняют. Новый завершённый запрос учитывается отдельно.
- Повторно используем завершённый ход, его проверенные ссылки и запись пробела. В `main` уже сохраняются `assembly_gaps` и `assembly_faq_uses`. Для аналитики нужны группировка и связь пробела с конкретной частью запроса и редакцией пункта, если такая связь установлена. Подтверждённые расхождения берём из результата сверки Отдела качества. Сохраняем причину структурированно, чтобы отчёт не зависел от формулировки сообщения в чате. ### Повторяющиеся вопросы без ответа

- За последние 30 календарных дней по МСК показываем общее число отдельных обращений с профильным пробелом, включая случаи, где бот ответил только на часть вопроса. Источник — сохранённые `assembly_gaps` и связанные ходы. Факт пробела учитывается и при отказе отправлять письмо. Разъяснение, полученное позже, сохраняет исторический факт, что бот не нашёл ответа на исходный запрос.
- Каждая строка содержит понятную тему, существенные условия и число обращений. Показываем группы от двух обращений, сначала самые частые. После входа в Отдел качества строка раскрывается в список фактических вопросов. Для каждого обращения берём исходную реплику сотрудника, в которой он задал вопрос. Для составного запроса в раскрытии видна исходная формулировка, а в группировку идёт только часть с пробелом.
- Один кейс учитывается в одной группе один раз. Два разных кейса с одной нерешённой частью учитываются отдельно. Общий счётчик по экрану считает уникальные кейсы и учитывает одиночные вопросы. При повторной обработке сохраняется связь события с группой. Исходный текст возвращает только API с проверкой роли Отдела качества. Сводка содержит тематику без имён сотрудников и контактов.

**Каскад группировки.** После сохранения пробела фоновый воркер получает нерешённую часть вопроса и подтверждённые условия. PostgreSQL подбирает кандидатов по тексту и глоссарию, существующий MiniLM ранжирует пары «пробел и похожая группа». **Gemma 4 26B A4B IT** (`google/gemma-4-26b-a4b-it`) выбирает существующую группу только при совпадении цели вопроса и всех условий, меняющих ответ. Для новой группы Gemma формулирует короткое название. Явно несовместимые условия отсекаются до вызова модели. При неоднозначности или отсутствии подходящей группы создаём отдельную группу. Неизвестное условие не заменяем предположением. Технический сбой сохраняет событие для повтора. Просмотр статистики читает готовый результат. ### Оценки ответов

- В браузерном «Демо DION» под содержательным ответом показываем 👍 и 👎. Можно оценить полный или частичный ответ и итоговое разъяснение Отдела качества, которое вернулось в чат. Кнопки имеют подписи «Помогло» и «Не помогло» для доступного управления.
- Одна активная оценка на сообщение от владельца диалога. Выбор второго варианта заменяет оценку. После обновления страницы виден текущий выбор. Сервер проверяет владение диалогом и допустимость сообщения для оценки.
- В «Статистике» показываем отдельные суммы 👍 и 👎 для ответов, полученных за последние 30 календарных дней по МСК. Считаем фактические оценки с учётом изменений. Период определяется датой ответа.

### Счётчик применений FAQ

- На строке каждой карточки в «Разъяснениях отдела» показываем «Использовано N раз» с правильной формой числа. Новая карточка начинает с «Использовано 0 раз». Счётчик за всё время относится к карточке и сохраняется после правки или отзыва.
- Один завершённый ответ даёт одно применение карточки, если её разъяснение послужило основанием хотя бы для части выданного ответа. Повтор обработки хода сохраняет одно применение. При выдаче регламента с предупреждением о конфликте отдельно различаем основания ответа и показанные альтернативные позиции. Счётчик берём из фактических применений по `turn_id` и `faq_id`.
- Для единственной заранее загруженной учебной карточки по ДБРЦТ отображаем «Использовано 5 раз» плюс последующие фактические применения. Пять — стартовое значение только этой карточки в демо. Оно не создаёт событий применения и не переносится на карточки из новых писем.

### Приёмка аналитики

1. Один ответ с двумя пунктами одного регламента и отдельный запрос, получивший ссылку на тот же регламент, дают две выдачи. Повтор обработки любого из ходов сохраняет итог. Документ, полученный только как кандидат поиска или уточнения, в список не попадает.
2. По одному пункту зарегистрированы один профильный пробел и одно подтверждённое расхождение FAQ. Гость видит две отдельные цифры и открывает этот пункт в указанной редакции. Повторная проверка FAQ сохраняет одну запись. После отмены карточки или снятия расхождения остаётся один пробел.
3. Вопрос без проверенного пункта увеличивает строку «Без привязки к пункту». Составной вопрос с правильным ответом на одну часть и пробелом в другой не превращает цитату к первой части в проблемный пункт.
4. Пустой период отображается как отсутствие данных. На сводке видны агрегаты по темам. Исходные вопросы доступны Отделу качества в раскрытии.
5. «Когда назначат РП?» и «Сколько ждать назначения руководителя проекта?» с одинаковыми существенными условиями образуют одну группу с числом 2. Одинаковая фраза из другой дирекции с другой применимой нормой остаётся отдельно. Повтор хода в первом кейсе сохраняет 2. После входа раскрытие показывает обе исходные формулировки, а прямой запрос от гостя возвращает только сводку.
6. В своём диалоге сотрудник ставит 👍, видит один голос в «Статистике» и после обновления видит свой выбор. При смене на 👎 первый счётчик уменьшается, второй увеличивается. Повтор команды сохраняет результат. Чужое сообщение оценить нельзя.
7. Учебная карточка показывает «Использовано 5 раз». Новая карточка из письма показывает «Использовано 0 раз». Следующий вопрос получает ответ на её основании, на карточке появляется «Использовано 1 раз». Повторная доставка ответа сохраняет 1.

## 2. Открытие полной редакции регламента

**Результат для сотрудника.** В DION можно явно попросить ссылку на регламент и открыть его целиком. Из точечной цитаты можно перейти к полной редакции на этом пункте.

| Действие сотрудника | Что делает стенд |
| --- | --- |
| «Где посмотреть регламент по пресейлу дирекции ИБ?» | По доступному каталогу находит «Пресейловая деятельность Дирекции ИБ». Возвращает полное название, номер действующей редакции и действие «Открыть регламент». Если запрос содержит известный номер пункта, ссылка открывает этот пункт внутри редакции. |
| «Где регламент по проектной деятельности?» | Когда из запроса и актуального контекста подходят несколько дирекций, показывает подходящие названия и просит выбрать. После выбора возвращает ссылку на действующую редакцию выбранного документа. |
| Сотрудник открыл цитату в обычном ответе | В просмотрщике пункта доступно действие «Открыть регламент целиком». Оно открывает то же издание, из которого взята цитата, и ставит пользователя на процитированный пункт. |
| Сотрудник открывает регламент из «Источников» | Открывается полная действующая редакция в приложении. Название, версия и ссылка на оригинал берутся из доступного снимка. |
| Регламента нет среди доступных документов | Бот сообщает, что не нашёл доступной редакции. Если в проверенном источнике есть надёжная отсылка, указывает название и известную разрешённую ссылку. Для профильного запроса предлагает существующий маршрут в Отдел качества. |

- Поиск ссылки выделяем по намерению сотрудника открыть документ. Находим документ по официальному названию, известному сокращению или однозначно указанной дирекции и теме. Обычный вопрос «Кто назначает РП в Дирекции ИБ?» по-прежнему получает конкретную инструкцию и точечную цитату. Ссылки на редакции формируются из каталога.
- Единый просмотрщик открывает сохранённый полный снимок редакции. В демо он использует оригиналы четырёх выданных DOCX. В представлении видны название, номер редакции, весь текст в порядке документа и пункт при переходе из цитаты. Для загрузки из Confluence можно использовать сохранённое тело конкретной редакции. Вариант просмотра и вид кнопки определяются финальным макетом.
- Адрес привязан к ID документа, ID редакции и, если есть, якорю. Для нового поиска выбирается действующая редакция. Историческая ссылка из чата ведёт в процитированную редакцию с пометкой «Историческая», пока она доступна сотруднику. Сервер проверяет права при поиске, чтении полной редакции и открытии оригинала. ### Приёмка открытия регламента

1. Гость своими словами просит открыть регламент пресейла ИБ. Видит название и номер действующей редакции. По ссылке открывается полный документ, который можно прокрутить вперед и назад от любого пункта.
2. Гость спрашивает, где искать регламент по проектной деятельности, без указания дирекции. Получает выбор из подходящих документов. После выбора открывается выбранный документ.
3. Сотрудник получает ответ с точной цитатой. Из этой цитаты открывает весь документ на соответствующем пункте. После импорта новой редакции новый навигационный запрос открывает её, а старая ссылка из диалога открывает прежнюю доступную редакцию на старом пункте.
4. Запрос к отсутствующему регламенту обрабатывается как отсутствие доступного документа. Прямой адрес недоступной редакции не раскрывает её текст. Обычный вопрос о порядке действий продолжает давать ответ с точечной цитатой.

## Что учесть в финальных макетах

- В «Статистике» разместить востребованные регламенты, проблемные пункты, повторяющиеся вопросы с раскрытием и оценки ответов. Показать период, пустые состояния и переходы. В «Разъяснениях отдела» добавить счётчик на строку карточки, а в Демо DION — 👍 и 👎 под содержательным ответом.
- В «Демо чат DION» показать найденный документ, выбор дирекции и состояние без доступной редакции. В существующем просмотре цитаты и в каталоге «Источники» показать переход к полной редакции с названием, версией и нужным пунктом.
- Принимать обе доработки в одной сборке с финальными макетами. Для приёмки нужны рабочие ссылки на оригинальные редакции и аналитика из серверных фактов. [Текущие макеты](https://chatgpt.com/library?file_id=libfile_77f91857fd488191b8f059b71557c477&account_id=personal)
