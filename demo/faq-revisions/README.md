# Как меняется ответ FAQ при обновлении регламента

Автономный пример показывает, что увидят автор обращения и другой сотрудник, когда разъяснение эксперта расходится с регламентом. Три исходных пункта взяты из регламента ДБРЦТ в [учебном корпусе](../../corpus/). Переписка и вторая редакция подготовлены для показа.

Откройте локальный [index.html](index.html) в браузере. Пример работает без почтового сервера, Confluence и ключей моделей. Кнопка «Начать заново» возвращает исходное состояние. Для проверки почты и автоматической индексации на работающем стенде используйте [руководство по демостенду](../../docs/architecture/product-release.md).

## Сценарий показа

1. Во «Входящих письмах» откройте «Срок точной оценки». Эксперт указывает 2 рабочих дня. В п. 1.6 регламента пока указано 5. Раскройте «Что получает автор обращения».
2. Нажмите «Подтвердить ответ эксперта», затем «Что увидит другой сотрудник». В чате появятся обе позиции со ссылками на источники. Для точной оценки действует срок по регламенту — 5 рабочих дней.
3. Вернитесь в «Изменения регламентов» и нажмите «Проверить изменения в Confluence». В учебной редакции 2 срок изменился на 7 рабочих дней. Откройте источник и убедитесь, что ссылка ведёт к обновлённому пункту. Новый п. Д.1 закрывает другой вопрос — о фиксации передачи оценки. Соответствующая карточка автоматически переходит в архив.

В карточке с расхождением можно отозвать разъяснение. После подтверждения новый диалог применит регламент, а прежний ответ и письмо останутся в истории.

## Проверки

Из корня репозитория выполните тесты модели FAQ и проверку приоритета источников на учебных примерах.

```sh
node --test demo/faq-revisions/model.test.cjs
node eval/faq-priority/evaluate.cjs
```
