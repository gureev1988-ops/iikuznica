# Как отдел качества ведёт FAQ

Открой `demo/faq-revisions/index.html` в браузере. В общем макете чата тот же экран открывается кнопкой «Отдел качества». Для показа достаточно файлов из этой папки. Кнопка «Начать заново» возвращает исходное состояние.

## Показ для жюри · около минуты

1. Открой «Входящие письма» и проверь письмо «Срок точной оценки». Эксперт указывает 2 рабочих дня на точную оценку в ДБРЦТ. Пока в п. 1.6 Confluence указано 5. Раскрой «Что получает автор обращения», чтобы увидеть разъяснение для него. Рядом можно проверить, что получает другой сотрудник из общего FAQ до публикации этого письма.
2. Нажми «Подтвердить ответ эксперта», затем «Что увидит другой сотрудник». Теперь видны 5 дней по регламенту и 2 дня по письму качества. В чате открываются оба источника. Рекомендация по бюджетной оценке и условие о времени на поиск и согласование подрядчика сохраняются.
3. Вернись в «Изменения регламентов» и нажми «Проверить изменения в Confluence». Владелец уже опубликовал версию 2 в вики. Теперь в ней 7 дней на точную оценку. Действующий регламент определяет срок в 7 дней, письмо качества остаётся вторым источником. Ссылка на расхождение ведёт к новой версии. В том же обновлении п. Д.1 полностью закрыл вопрос, где зафиксировать передачу оценки. Его карточка автоматически уходит в архив.

Служба качества может отозвать своё разъяснение. Открой «Отозвать разъяснение…» у активного ответа с расхождением. «Отмена» сохраняет его в силе. После «Подтвердить отзыв» новый диалог использует применимый регламент. Письмо, решение службы и старые ответы остаются в истории.

Оба процесса можно проверить в обратном порядке. Повторное чтение той же версии сохраняет решения. История диалога в общем макете сохраняет редакцию и источники каждого ответа.

## Правила проверки

Сначала система проверяет автора и применимость разъяснения к вопросу. Затем сравнивает утверждения с актуальной редакцией регламента. В этом автономном макете кнопка подтверждения переключает подготовленное состояние FAQ. Чат при расхождении показывает обе позиции и применяет действующий регламент. В приложении доверенное письмо индексируется автоматически и при расхождении попадает в очередь проверки. [Спецификация](../../docs/IIkuznitsa_Kickoff_Spec.md). Письмо с неподтверждённым авторством или другой областью действия требует проверки.

В демо письмо «Три дня на оценку» иллюстрирует неясную формулировку. После уточнения автора становится понятно, что речь о бюджетной оценке. Три дня совпадают с регламентом, а пометка в теме письма дополняет его. Неоднозначность и конфликт с регламентом дают разные основания для решения.

Три исходных пункта взяты из файла «Проектная деятельность ДБРЦТ» в `corpus/`. История новой версии и переписка подготовлены для показа. Браузер читает снимок истории, а связи и значения для сравнения заданы в примере. Корпоративная почта, Confluence и модели к этому экрану не подключены.

## Запуск в Codex

Из корня репозитория выполни тесты.

```sh
node --test demo/faq-revisions/model.test.cjs
```

Отдельная приёмка на учебных данных оценивает два результата — выбор приоритетного источника и обнаружение расхождения. Запусти из корня репозитория `node eval/faq-priority/evaluate.cjs`.

Для локального показа запусти сервер и открой [демо](http://localhost:8000/demo/faq-revisions/).

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Компонент `<faq-revision-demo>` посылает событие `faq-ask` с идентификатором вопроса. `chat-view.js` формирует снимок ответа для общего чата с письмом и версиями применимых пунктов.
