# Проверка FAQ при смене регламента

Интерактивный эпизод для жюри ИИкузницы. Открой `index.html` в браузере или подключи `<faq-revision-demo>` к экрану отдела качества. Для показа не нужны сеть, ключи моделей и установка пакетов.

1. В отделе качества видно, что ответ о сроках опирается на пп. 1.6 и 1.7 ДБРЦТ. Рекомендуемый срок точной оценки — 5 рабочих дней.
2. Нажми «Импортировать деморедакцию». Условная редакция меняет только 5 на 7 в п. 1.6. Появляются сравнение версий и один ответ на проверку. У второго ответа источник — п. 1.1.1 того же документа.
3. Нажми «Спросить в чате» до утверждения. Сотрудник получит правило по действующей деморедакции и увидит прежний FAQ с отметкой о расхождении. Раскрой п. 1.7, чтобы показать сохранившуюся оговорку о подрядчике.
4. Вернись в отдел качества, нажми «Утвердить ответ» и повтори вопрос. Теперь источником выступает подтверждённый FAQ. «Начать заново» возвращает исходное состояние.

Пункты взяты из оригинала «Проектная деятельность ДБРЦТ» в `corpus/`. Редакция со сроком 7 дней и подписи отдела качества являются демонстрационными. Данные хранятся в памяти вкладки. При импорте код сравнивает текст пунктов, находит связанные ответы по паре «документ, номер пункта» и переводит их на пересмотр. В этой версии черновик обновлённого ответа подготовлен для учебного примера. Утверждение привязано к конкретной редакции и проверяемым основаниям.

`model.js` реализует версии и статусы FAQ. `ui.js` и `ui.css` реализуют экран отдела качества. Событие `faq-ask` передаёт идентификатор выбранного вопроса, `chat-view.js` создаёт снимок ответа с версиями и цитатами. Интерактивный макет чата проекта использует этот же модуль.

Проверка модели:

```sh
node --test demo/faq-revisions/model.test.cjs
```
