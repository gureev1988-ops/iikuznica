# Контроль FAQ отдела качества

Открой `demo/faq-revisions/index.html` в браузере. В общем макете чата тот же экран открывается кнопкой «Отдел качества». Для показа достаточно файлов из этой папки. Данные одного сеанса хранятся в памяти вкладки.

## Сценарий для жюри · около минуты

1. На вкладке «Изменения регламентов» нажми «Проверить изменения в Confluence». Владелец уже опубликовал новую версию в вики. Раскрой изменения в п. 1.6 и в новом п. Д.1. Первый меняет рекомендуемый срок точной оценки с 5 до 7 рабочих дней. Второй полностью закрывает вопрос, где зафиксировать передачу оценки. Соответствующее разъяснение автоматически уходит в архив FAQ.
2. У прежнего ответа про 5 дней нажми «Удалить из FAQ…». Сверь старый ответ с новым пунктом и подтверди удаление. «Спросить в чате» покажет сотруднику 7 дней со ссылкой на п. 1.6. Для привлечения подрядчика по-прежнему учитывается время поиска и согласования по п. 1.7. Даже если отложить решение об удалении, спорный ответ уже снят с выдачи.
3. Переключись на «Входящие письма» и проверь письмо про срок точной оценки. В нём указаны 2 дня для тех же условий, поэтому оно попадает на модерацию. Рядом видны исходное письмо и действующий пункт. Затем проверь письмо про тему запроса о получении оценки. В регламенте эта деталь отсутствует, и сотрудник может получить подтверждённое разъяснение из FAQ.

Можно пройти сценарии в другом порядке. Повторная проверка той же версии сохраняет принятые решения. Каждая цитата в истории общего чата сохраняет исходную редакцию.

## Данные и порог модерации

Три исходных пункта взяты из файла «Проектная деятельность ДБРЦТ» в `corpus/`. Вторая редакция, история страницы и письма подготовлены для демонстрации. Браузер читает снимок внешнего журнала. Корпоративная вики и почта к этому эпизоду не подключены.

Правило сравнивает размеченные утверждения в применимых пунктах. Разный срок для одной и той же оценки отправляет письмо модератору. При неопределённом виде оценки требуется уточнить область применения. Если письмо добавляет полезную подробность, которую регламент оставил открытой, её можно включить в FAQ после проверки. Полностью покрытый вопрос получает ссылку на регламент. Числовой порог для модели на реальных письмах предстоит калибровать отдельно.

## Запуск из Codex

Из корня репозитория запусти тесты модели.

```sh
node --test demo/faq-revisions/model.test.cjs
```

Для показа через локальный веб-сервер выполни команду и открой [демо](http://localhost:8000/demo/faq-revisions/).

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Компонент `<faq-revision-demo>` посылает событие `faq-ask` с идентификатором вопроса. Адаптер `chat-view.js` сохраняет в ответе доступные сотруднику основания на момент запроса.
