# Проверка пропущенного шага на Q04

Обе реплики отвечают на один опубликованный вопрос про пресейл ИБ. Первая воспроизводит черновик ядра. Из второй удалена только роль получателя в конце фразы о передаче ТКП. Ссылки, упоминания АМ в других ролях и входные источники одинаковы. Провайдер получает отдельный независимый запрос для каждой реплики без маркировки вариантов или эталона.

Decider выбирает тип существенного пропуска и строку из процитированного пункта. Доступны ответы «пропуска нет» и «основание вне перечисленных строк». Критерий успеха фиксирован до запуска. Для полной реплики оба выбора должны означать отсутствие пропуска. Для сокращённой нужны «получатель» и строка пресейла ИБ §1.3 про явный отказ от услуг, подготовку ТКП и передачу АМ. Зачёт по двум выборам одновременно. Эта проверка измеряет различение одной пары. Решение о публикации сотруднику и порог в рабочем ядре не меняются.

Пригодность входов и совпадение цитат с оригиналами можно проверить без ключа:

```sh
python3 eval/scope/judge_pair.py --check
```

В окружении с `OPENROUTER_API_KEY` выполнить:

```sh
python3 eval/scope/judge_pair.py --out /tmp/iikuznica-q04-pair
```

Успешные ответы сохраняются в каталоге запуска по хешу полного запроса. Повтор той же команды использует их повторно. Отчёт `summary.json` содержит выбор, уверенность, цитату, время и стоимость для каждой реплики. Код не создаёт ответов судьи при отсутствии доступа к API.

## Что показала проверка 26 ноября

По результатам запуска Кирилла на `c9b1bb8` судья для обоих черновиков вернул `gap=none` и `basis=p4`. Правильных пар решений 0/2. Отдельно тип пропуска распознан в 1/2 случаев. В сокращённом черновике судья нашёл нужную строку регламента, но пропустил отсутствие получателя в самой реплике.

Для ответов, собранных из утверждений реестра, проверили другой способ. Код ищет полный текст каждого обязательного утверждения в итоговой реплике и сверяет привязанную к нему ссылку. Отдельно проверяет совпадение всей реплики с выбранным набором утверждений. Метод рассчитан на дословную сборку из реестра. Свободные пересказы требуют отдельной оценки.

| Черновик | Подтверждение передачи ТКП аккаунт-менеджеру в реплике |
|---|---|
| Полный | Найдена фраза «BDM формирует ТКП только на поставку и направляет его АМ» со ссылкой на пресейл ИБ §1.3 |
| Получатель удалён | Подтверждения нет |
| Получатель заменён на SS, АМ упомянут при создании заявки | Подтверждения нет |

Команда `python3 eval/scope/check_rendered_plan.py` воспроизводит три варианта без API. Дополнительная проверка выявила ограничение. Если спросить ещё и о сроке передачи ТКП, текущий генератор собирает тот же черновик, который по-прежнему точно совпадает с выбранными утверждениями. Поэтому совпадение по тексту не даёт оснований автоматически публиковать ответ.

В рабочем банке из 50 вопросов правило для этой процедуры срабатывает только на Q04. Ближайшая проверка — выделить каждую просьбу сотрудника и потребовать для неё подтверждение или явный ответ об отсутствии данных. Включить составные вопросы и другие процедуры.
