# Область вопросов и обращение в отдел качества

Кандидат для прототипа поверх `links_threshold`. Вход — вопрос сотрудника и, для следующей реплики, исходный вопрос. Выход — действие, текст, источники и признак `offer_quality_request`. Веб-клиент показывает кнопку отправки, только когда этот признак равен `true`. Письмо требует отдельного подтверждения сотрудником. Отправка почты и веб-интерфейс в этом модуле отсутствуют.

| Что спрашивает сотрудник | Поведение |
|---|---|
| Личный совет о повышении зарплаты или явно бытовой вопрос | Короткая доброжелательная шутка. Без кнопки отправки. |
| Формальный кадровый или чувствительный личный вопрос | Спокойно обозначить область помощника. Без шутки и обращения в отдел качества. |
| Непонятно, речь о личной ситуации или о процессе проекта | Уточнить, какой проектный шаг имеет в виду сотрудник. |
| Профильный вопрос по проекту или пресейлу | Найти пункты и проверить ответ. При нехватке сведений о ситуации уточнить её. Если подтвердить инструкцию по источникам не удалось, предложить обращение. |

Для короткой явной просьбы помочь повысить собственную зарплату есть локальное правило на полную фразу. Слова «зарплата» и «оклад» по отдельности его не включают. Для остальных вопросов Decider оценивает тему в том же вызове, в котором проверяет ответ. Нового обращения к API ради классификации нет. При неуверенной классификации показываем уточнение. Порог темы 0,70 экспериментальный.

## Проверка

Локальное правило и тесты политики можно запустить без ключа.

```sh
python3 eval/scope/ask.py 'А как мне повысить себе зарплату?'
python3 -m unittest discover -s eval/scope
```

Для произвольного вопроса нужны установленные зависимости из `eval/retrieval/package-lock.json`, Python с ONNX Runtime, NumPy и tokenizers, [веса MiniLM из опыта](../rerank/README.md) и переменная `OPENROUTER_API_KEY`. Пример запуска из корня репозитория:

```sh
python3 eval/scope/ask.py 'Как учитывать ФОТ команды в бюджете проекта?' --model-dir /path/to/minilm --python /path/to/onnx/python
```

Проверки политики подают контролируемые решения судьи. Качество распознавания произвольных формулировок требует отдельного слепого прогона. Для него считаем две ошибки по отдельности — предложение отправить посторонний вопрос и отказ по профильному вопросу без основания. Дополнительно проверяем долю пригодных ответов на вопросы с источником. Предыдущая [сводка Final15](../final15/results-summary.md) относится к исходной версии без этого фильтра.
