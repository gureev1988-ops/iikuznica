# Область вопросов и обращение в отдел качества

Кандидат для прототипа поверх `links_threshold`. Вход — вопрос сотрудника и, для следующей реплики, исходный вопрос. Выход — действие, текст, источники и признак `offer_quality_request`. Веб-клиент показывает кнопку отправки, только когда этот признак равен `true`. Письмо требует отдельного подтверждения сотрудником. Отправка почты и веб-интерфейс в этом модуле отсутствуют.

| Что спрашивает сотрудник | Поведение |
|---|---|
| Личный совет о повышении зарплаты или явно бытовой вопрос | Короткая доброжелательная шутка. Без кнопки отправки. |
| Формальный кадровый или чувствительный личный вопрос | Спокойно обозначить область помощника. Без шутки и обращения в отдел качества. |
| Непонятно, речь о личной ситуации или о процессе проекта | Уточнить, какой проектный шаг имеет в виду сотрудник. |
| Профильный вопрос по проекту или пресейлу | Найти пункты и проверить ответ. При нехватке сведений о ситуации уточнить её. Если подтвердить инструкцию по источникам не удалось, предложить обращение. |

Для короткой явной просьбы помочь повысить собственную зарплату есть локальное правило на полную фразу. Слова «зарплата» и «оклад» по отдельности его не включают. Для остальных вопросов Decider оценивает тему в том же вызове, в котором проверяет ответ. Нового обращения к API ради классификации нет. При неуверенной классификации показываем уточнение. Порог темы 0,70 экспериментальный.

## Проверка

Локальное правило и тесты политики можно запустить без ключа.

```sh
python3 eval/scope/ask.py 'А как мне повысить себе зарплату?'
python3 -m unittest discover -s eval/scope
```

Для произвольного вопроса нужны установленные зависимости из `eval/retrieval/package-lock.json`, Python с ONNX Runtime, NumPy и tokenizers, [веса MiniLM из опыта](../rerank/README.md) и переменная `OPENROUTER_API_KEY`. Пример запуска из корня репозитория:

```sh
python3 eval/scope/ask.py 'Как учитывать ФОТ команды в бюджете проекта?' --model-dir /path/to/minilm --python /path/to/onnx/python
```

Проверки политики подают контролируемые решения судьи. Качество распознавания произвольных формулировок требует отдельного слепого прогона. Для него считаем две ошибки по отдельности — предложение отправить посторонний вопрос и отказ по профильному вопросу без основания. Дополнительно проверяем долю пригодных ответов на вопросы с источником. Предыдущая [сводка Final15](../final15/results-summary.md) относится к исходной версии без этого фильтра.

## Эксперимент с ответами из реестра норм

Вариант `ask.py --evidence` сохраняет пять исходных пунктов и их связи. Когда в выдаче несколько дирекций, он дополнительно берёт до двух кандидатов от каждой по совокупности текстового и семантического рангов. Gemma выбирает утверждения из проведённой до прогона разметки оригиналов. В прямом ответе код показывает только текст выбранных утверждений и привязывает каждое к своему пункту. Decider получает именно этот текст и оригиналы. Неверный выбор утверждения и пропуск условия по-прежнему возможны.

Сравнить доступность эталонных источников без ключа можно из корня репозитория на прежнем приватном пакете:

```sh
python3 eval/scope/run50.py IIkuznitsa_Final15.zip --check
```

В облачной сессии с тем же ZIP и `OPENROUTER_API_KEY` запусти полный эксперимент:

```sh
python3 eval/scope/run50.py IIkuznitsa_Final15.zip
```

Для этих 50 запросов используются сохранённые варианты поиска BM25 и MiniLM. Повторная установка весов не требуется. Каждый успешный API-вызов сохраняется для возобновления. После сбора 50 реплик скрипт присоединяет эталоны и тексты процитированных и ожидаемых пунктов в `procedures50-private/<модель>/review.jsonl`. Приватные входы, ответы и ключи оценки остаются вне Git.

Зачёт реплики требует верного действия, применимых и полных указаний с подтверждающими ссылками или конкретного уместного уточнения, отказа либо предложения эскалации. После ручной сверки каждой строки цель на знакомом банке — **50/50**. Затем фиксируем версию и один раз оцениваем **20 новых** вопросов по тому же правилу. Порог — **19/20**. Эталонные ответы и номера вопросов не входят в запросы к моделям.

## Текущий кандидат и парное сравнение

В новой версии карточки ДБРЦТ и ИБ уточнены по оригиналам. Ветви пресейла ИБ про явный отказ от услуг, наличие хардоффера и долю стоимости описаны отдельно. При выборе некоторых утверждений код добавляет подтверждённое обязательное условие перед проверкой судьёй. Случаи назначения РП, получения заявки на расчёт, состава установочной встречи и контроля поставки используют различия между регламентами. Предметный поиск для телефона, размера файла и замещения проверяет весь применимый корпус и учитывает, о каком объекте спрашивает сотрудник. У остальных запросов сохраняется модельная проверка. Уточнения принимают историю сообщений сотрудника; в интерактивном режиме варианты из ответа помощника не считаются фактами.

Из корня репозитория выполните `python3 eval/scope/run50.py IIkuznitsa_Final15.zip --check`. Команда проверяет локальные конечные реплики на рабочем банке и воспроизводит значения порога на ранее записанных вызовах linked35. Качество новых ответов генератора оценивается отдельно.

Для слепого сравнения базовой модели и старшей модели используйте команду:

```sh
python3 eval/scope/run50.py IIkuznitsa_Final15.zip --compare-models
```

Обе модели получают один корпус, поиск и правила отбора. Поиск из замороженных пулов дополняют одинаковые правила для процессов. Perplexity Decider Flash и порог 0,50 одинаковы. Оплата зависит от фактического расхода токенов. Добавочные вызовы старшей модели возникают только при запуске парного режима. При обрыве повторите команду с тем же каталогом, чтобы восстановить вызовы. `procedures50-private/paired-review.jsonl` содержит анонимизированные стороны A/B для каждого вопроса, оригиналы и эталон. Сначала поставьте каждой стороне зачёт или опишите необходимое исправление. Затем откройте `unblind.json`. Сопоставьте в том числе ответы с прежними 13 ошибками и 37 пригодными репликами. У каждой модели свои `review.jsonl`, `measurements.json` и `threshold-replay.json`. Время в отчёте относится к модельным вызовам. Файлы проверки остаются приватными.

Ядро принимает снимки публикаций из контура службы качества. Для каждой записи нужны `snapshot` в формате `model.query(...)` и, при наличии, `approved_aliases`. В вызов передаётся область обращения. Для повторного использования подходят только опубликованная подтверждённая формулировка, её проверенный эквивалент и та же область применения. При расхождении с вики сохраняются письмо, автор, дата и противоречащий фрагмент. Запрос создаётся через регистратор только после подтверждения пользователя. Тестовый регистратор и письма в проверке синтетические. Запуск проверки — `python3 -m unittest discover -s eval/scope` и `node eval/faq-priority/evaluate.cjs`.
