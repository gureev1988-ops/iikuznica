# Связанные пункты, проверка условий и уверенность в действии

База сравнения — [проверенные ответы Gemma + Decider](../decider/results/analysis.md) на 35 рабочих вопросах. Отложенные 15 вопросов в эксперимент не входят.

## Запуск

Из корня репозитория в окружении с OPENROUTER_API_KEY выполни:

    python3 eval/linked35/experiment.py

На Linux и macOS достаточно Python 3.9+. Для офлайн-проверки документов, связанных пунктов и изменения действий по старым ответам:

    python3 eval/linked35/experiment.py --check

Добавь `--offline-report eval/linked35/preflight.json`, чтобы заново записать [результаты офлайн-проверки](preflight.json). Основной запуск сохраняет ответы в `eval/linked35/results`. После ошибки API повторная команда в том же каталоге продолжит прогон с последнего сохранённого вызова. Для новой независимой попытки укажи `--out` с новым путём.

## Что сравниваем

| Вариант | Источники и обработка |
|---|---|
| baseline | Опубликованные черновики Gemma, решения Decider и итоговые реплики. |
| links | Та же Gemma, инструкция и настройки генерации. Пять исходных пунктов сохранены в том же порядке. Из реестра добавляем до 15 прямо связанных пунктов, по очереди от каждого из пяти. Затем обрабатываем черновик прежним судьёй и по прежним правилам повторного поиска. |
| conditions | Те же генерации и решения варианта links. Перед показом прямого ответа Decider по каждому утверждению из переданных пунктов определяет, применимо ли оно и отражено ли в тексте. Получает формулировку из реестра вместе с оригиналом. При существенном пропуске Gemma один раз переписывает ответ по замечаниям. Повторная проверка маршрута и условий разрешает показ или переводит вопрос в уточнение либо эскалацию. |
| Суффикс _threshold у каждого варианта | Если судья разрешил прямой ответ с уверенностью в действии ниже 0,5, код выбирает безопасное завершение. Когда среди альтернатив лидирует уточнение и известен недостающий признак, задаёт соответствующий вопрос. В остальных случаях предлагает обращение в службу качества. Это последнее действие перед показом, дополнительных вызовов API нет. |

Эффект проверки условий сравниваем между links и conditions на одних и тех же исходных черновиках. Результат links сравниваем с историческим прогоном генерации. При таком сравнении возможен разброс двух запусков модели. Варианты с порогом используют уже полученные ответы тех же моделей, поэтому их действия можно сравнить точно. Правило проверяется на рабочей выборке, где ошибки уже разбирали. Оно требует независимой оценки на отложенных вопросах.

## Что измерено без новых вызовов

На сохранённых решениях порог и правило завершения меняют Q11 с прямого ответа на уточнение дирекции, Q20 — с прямого ответа на предложение отправить обращение. Итог — 35/35 совпадений по действию вместо 33/35. Первый вопрос к сотруднику в Q11 ещё не устанавливает, идёт ли речь о поставке или услугах. Следующий ход диалога здесь не проверяется.

Среди 28 прямых вопросов полный набор эталонных пунктов найден для 28 вместо 26. Улучшились Q05 и Q22. У Q22 в выдаче теперь 8.4–8.8 вместо одного 8.5. Для Q10 оба эталонных пункта уже были в исходной выдаче. У четырёх неоднозначных вопросов всё ещё отсутствует часть эталонных источников. Число входных пунктов с учётом связей — от 8 до 19, медиана 13. Увеличение объёма контекста входит в цену и задержку живого варианта.

## Как читать живой результат

После 35 вопросов проверь `summary.json` (complete), `outcomes.jsonl` и `review.md`. Последний файл сопоставляет реплики с оригиналами. По Q10 проверь дополнительный срок на подрядчика. По Q22 проверь обе ветки старта работ, необходимые согласования и действия при срыве срока. По Q11 и Q20 проверь, что текст соответствует действию в интерфейсе. Укажи, сколько из шести корректных контрольных ответов потеряли прямой ответ и сколько потребовали лишней переработки. Совпадение действия «ответить» не устанавливает полноту инструкции сотруднику.

Сводка считает p50/p95 последовательного времени успешных API-вызовов на вопрос и расходы в USD для одного варианта. Локальный поиск и отрисовка интерфейса не входят. Варианты с общей генерацией повторно используют результаты. Нельзя складывать стоимости шести вариантов как счёт за запуск. Файлы `calls/` позволяют пересчитать расходы только на новые вызовы. Промежуточные состояния сохраняются на случай квоты API или разрыва сети.
