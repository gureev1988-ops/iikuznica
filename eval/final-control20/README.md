# ИИкузница · финальный контроль из 20 вопросов

В наборе 5 простых вопросов и 15 по наблюдавшимся сбоям. Сложный блок проверяет составные просьбы, полноту процедур, точность ответа и связь с историей. Во входных репликах используются полные названия и естественные словоформы.

Пакет проекта `IIkuznitsa_Final_Control20.zip` содержит архив входов для оператора и отдельный комплект для проверяющего.

| Артефакт | SHA-256 |
|---|---|
| `IIkuznitsa_Final_Control20_Inputs.zip` | `f3dffeab4539303e5363f4b411b8827a5bb295ef201c323dd03474f915828ce2` |
| `IIkuznitsa_Final_Control20_Reviewer.zip` | `47c45236d69a28ffb55f42cfc30c66b124e7c18e715aae2f1b80b703aa48463b` |

## Запуск

1. Зафиксируй SHA и конфигурации кандидатов, редакции регламентов и снимок FAQ. Передай оператору архив входов.
2. Запусти каждый ID в отдельной сессии. Для случаев с историей передай последовательность реплик с указанными ролями, затем целевой вопрос. Для A1 подойдёт существующий раннер [PR #26](https://github.com/gureev1988-ops/iikuznica/pull/26). Для другого кандидата используй его точку запуска с теми же входами.
3. Сохрани по одному видимому ответу на каждый ID. Зафиксируй текст, действие, источники, предложение обратиться в качество и технические сбои.
4. После фиксации результатов сверь ответы с комплектом проверяющего. Порог — 19/20. Отдельно посчитай результаты по 5 простым и 15 сложным вопросам, ошибочные инструкции, пропущенные подтверждённые части и лишние уточнения или эскалации.

Пример для A1 при настроенном окружении и закреплённом MiniLM.

```sh
D=/workspace/scratch/answer-quality-pr26
python3 eval/conversations/answer_quality_trial.py --variant A1 \
  --blind20 /absolute/path/IIkuznitsa_Final_Control20_Inputs.zip \
  --model-dir "$D/minilm" --python "$D/venv/bin/python" \
  --out "$D/final-control20-a1"
```
