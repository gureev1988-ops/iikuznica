# Сравнение Gemma и Qwen с поиском

В корпусе лежат четыре оригинальных регламента. Кирилл подтвердил разрешение на их полную публикацию 26 ноября. Индекс содержит 622 пункта, включая текст подпунктов, продолжения и строки таблицы, привязанные к номеру пункта. Самостоятельный заголовок без текста пропускается.

Для каждого из 12 рабочих вопросов поиск возвращает до пяти пунктов. Текст обрабатывает русский полнотекстовый словарь PostgreSQL в PGlite. BM25 учитывает частоту терминов по всему корпусу, заголовок раздела и расшифровки из глоссария. Явное название дирекции ограничивает выдачу соответствующими документами. Эталоны подключаются только при оценке. В contexts.jsonl зафиксирован одинаковый вход для обеих моделей. Параметры генерации и системная инструкция взяты из первого опыта.

Параллельно Codex ведёт [эксперимент с реестром норм](../registry/README.md). В нём этот поиск служит контролем на тех же вопросах.

## Запуск двух моделей

Из корня репозитория в окружении с OPENROUTER_API_KEY:

```sh
python3 eval/run_12x3.py --search
```

Проверка `--search --check` работает без ключа. Генерация использует стандартную библиотеку Python 3.9+ на Linux/macOS. Успешные запросы сохраняются построчно в eval/retrieval/results/attempts.jsonl. Следующий запуск подхватывает прерванный прогон. Цель — 24 завершённых ответа. Таблица scores.csv содержит решение модели, совпадение действия, время и стоимость. Обоснованность каждого указания сверяется с найденными пунктами отдельно.

## Повторить поиск и оценку

Из корня репозитория, с Node 22+ и Python 3.9+:

```sh
npm ci --ignore-scripts --prefix eval/retrieval
node eval/retrieval/search.mjs
python3 eval/retrieval/evaluate.py
```

В retrieval_scores.csv указаны найденные, ожидаемые и пропущенные пункты. Колонка all_found проверяет, попали ли в пятёрку все уникальные эталонные ссылки. Для эскалации ссылка указывает ближайший относящийся к вопросу пункт. Наличие такой ссылки само по себе не доказывает, что ответа в регламентах нет.
