# Письма службы качества и изменения вики

Парный тест для эксперимента ИИкузницы. В нём 14 вымышленных ситуаций, семь входящих писем и семь изменений страницы. У каждого события четыре исходных пункта с отвлекающими вариантами. Отдельно опубликованы тексты, эталоны и оценщик. Данные придуманы для этой задачи и не входят в банк вопросов основного поиска.

A читает письмо или FAQ и исходные пункты. B получает те же тексты в том же порядке и дополнительные карточки утверждений. Построитель видит только регламенты. Код проверяет буквальное наличие цитаты, отдельный вызов модели проверяет смысл и полноту. Отклонённая карточка исключается, оригинал остаётся в выдаче. Пара сравнивает качество интерпретации уже найденных фрагментов. Обнаружение затронутых FAQ во всём корпусе и скорость интерактивного чата требуют отдельных замеров.

## Что проверено

- На одинаковых исходниках Codex решил 13/14 полностью в каждом варианте. [Слепые ответы, карточки и разбор F07](results/codex14/README.md)
- Gemma решила 7/14 по оригиналам и 5/14 с дополнительными карточками. Обе ветки нашли 4 из 5 конфликтов. С карточками стало больше ложных сигналов. [Результаты и расходы](results/gemma14/README.md)
- При обратном поиске по каталогу из 16 FAQ оба варианта вернули все пять затронутых записей. Три из них были без прежней ссылки на изменённый пункт. [Проверка поиска кандидатов](impact/README.md)

## Запуск в Codex Cloud

В окружении ИИкузницы с настроенным OpenRouter выполни из корня репозитория следующие команды. Для нового эксперимента используй свободный каталог. Повтор после ошибки с теми же параметрами продолжает существующий прогон.

```sh
cd eval/faq-reconciliation
python3 run.py live --cases cases.json --out /tmp/faq-gemma14 --model google/gemma-4-26b-a4b-it
python3 score.py --cases cases.json --gold gold.json --a /tmp/faq-gemma14/raw.json --b /tmp/faq-gemma14/registry.json --out /tmp/faq-gemma14/scores.json
```

Решающий вызов использует один пакет событий для каждого варианта. В `usage-summary.json` стоимость и время выполнения приведены отдельно для построения карточек, аудита, A и B. Время одного пакета не измеряет задержку ответа на единичный запрос. При поддержке выбранной моделью конкретного провайдера его можно зафиксировать опцией `--provider`. Неизвестная стоимость остаётся пустой.

## Как читать результат

В каждом случае оценщик сверяет вид смысловой связи, действие, приоритетный источник и минимальный набор подтверждающих цитат. Для письма источник определяется для исходного адресата, для изменения вики — для повторного вопроса сотрудника. Содержательное противоречие и полномочия автора оцениваются раздельно. Результат по отдельным критериям помогает отличить ошибочную публикацию от лишней ссылки при верном решении.

Первый эксперимент отвечает на вопрос, помогает ли дополнительное представление на одинаковых основаниях. Чтобы принять решение для хакатона, отдельно проверяем кандидатов на полном наборе FAQ, новые письма и редакции, пропущенные исключения и ошибочное снятие действующего ответа. Принятый FAQ можно передавать в основной поиск с областью действия, статусом и ссылкой на письмо. Кандидаты на модерации остаются в отделе качества.

Офлайн-пакеты воспроизводятся командой `python3 run.py prepare --cases cases.json --out /tmp/faq-packets`. После ответа построителя повтори её с `--cards <cards.json>`, после аудита добавь `--audit <audit.json>`. Файл `gold.json` открывает только оценщик.
