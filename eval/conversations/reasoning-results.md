Исходный SHA `92ad3a5b517fbd38139904d436b8cdf476bd0035` ветки `experiment/conversation-planner`. Сравнение на десяти первых ходах P01–P10. Blind20 в работу не входил.

## Условия и воспроизведение

`reasoning_trial.py` переиспользует поиск, расширение из `procedure_trial.py`, выбор утверждений, рендер ссылок, Decider и правила повторной попытки. Перед запуском фиксирует вопрос, инструкцию и упорядоченные оригиналы каждого набора в `frozen.json`, включая хеш на вопрос. A–D используют один расширенный набор. Контроль использует штатную выдачу прежнего живого ядра с тем же промптом COVER и тем же маршрутом, что A. В контроле полностью покрыты эталонные пункты 6/10 первых входов, после расширения 10/10. Ранее опубликованные 9/10 относятся к другому сравнению, где контроль уже раскрывал соседние разделы. Старые ответы 5/10 для контроля не переиспользованы.

У генераторов общий лимит 8192, температура 0, потоковый ответ, `reasoning.exclude=true`. Для Gemma закреплён `deepinfra/fp8`, для Qwen — `alibaba`. `require_parameters=true`, fallback выключен. Проба вернула `stop` и reasoning-токены 0/194 у Gemma и 0/349 у Qwen для выключенного и включённого режима. Проверка исключённого маршрута SiliconFlow для Qwen с reasoning дала HTTP 400 только на предварительной пробе. Финальные четыре режима проверены также на рабочих вызовах. Записаны запрошенная и фактическая модели, провайдер, параметры, статус завершения, доступный usage. Скрытые рассуждения не запрашивались в выдаче и не опубликованы.

```sh
python3 eval/conversations/reasoning_trial.py --probe --out /tmp/procedure-probe
python3 eval/conversations/reasoning_trial.py --out /tmp/procedure-reasoning
# Сначала оценить blind.json по оригиналам, зафиксировать оценки, затем открыть unblind.json.
npm ci --prefix eval/retrieval --ignore-scripts
python3 eval/conversations/reasoning_trial.py --winner C --model-dir "$MINILM_DIR" --python "$RERANK_PYTHON" --out /tmp/procedure-validate42
python3 eval/conversations/reasoning_trial.py --winner C --model-dir "$MINILM_DIR" --python "$RERANK_PYTHON" --working50 "$WORKING_ZIP" --out /tmp/procedure-validate50
```

По желанию `--reuse-calls` принимает каталог `calls` от прежнего `check.py` на совместимом наборе. Ключ OpenRouter берётся из окружения. Веса, ревизия и контрольные суммы описаны в [инструкции MiniLM](../rerank/README.md). Сырые файлы прогонов остаются локальными. ## Сквозная проверка варианта C

В восстановлении темы осталась Qwen 122B, в обычных ответах и уточнениях сохранился прежний маршрут. Для полного процесса требуется явная просьба о порядке действий или связка нескольких шагов. Признак проверяется и на исходной реплике, и на формулировке после разрешения темы. Это мешает короткому продолжению попасть в новый маршрут только потому, что восстановитель повторил предыдущий полный вопрос. Первый, более широкий фильтр направлял одиночный процессный вопрос и кадровую просьбу в маршрут процедур. После сужения правила обе серии повторены. В окончательной проверке правило выбрало десять первых процедур из 42 и ни одного из 50 обычных вопросов. ID и эталоны в правиле не используются.

Для диалогов использованы фактические предыдущие ответы каждой новой серии. Кеш копировался из прежних запусков и применялся по точному хешу запроса. Первые десять вызовов победителя также переиспользованы из слепого сравнения при полном совпадении. Оценки прежних реплик переносились только при точном совпадении действия, текста, ссылок и признака предложения обратиться в качество. Изменившиеся реплики сверены с оригиналами.

Потеряны два прежде пригодных продолжения. **P03.2** подменяет допуск на сайт по IB §4.3 условиями допуска субподрядчика к работам. **P10.2** заново спрашивает дирекцию вместо ответа по TECH §16.4. ## Вывод для демо

Для автономной полной инструкции на этой выборке лучше Qwen 122B без reasoning с расширенным поиском. Расширение добавило 2 из 10 пригодных ответов для Gemma при прочих равных. Reasoning не улучшил Gemma и ухудшил Qwen. Для многоходового демо разумнее оставить проверенный маршрут, пока не проверена устойчивость продолжений после расширенной инструкции. Прирост на один ход оплачен двумя регрессиями, количество целых диалогов прежнее. Результаты относятся к рабочей выборке.

## Проверка истории продолжений

Между `64afe0e` и `6193afae` реализация восстановления темы одинакова. У коротких P03.2 и P10.2 расширенный маршрут выключен. Вход модельного восстановителя включает текст первой инструкции. При связи с предыдущей темой код отклоняет добавленную дирекцию, но допускает потерю уже известной. В P03.2 «туда» относится к площадке проекта из вопроса сотрудника. В P10.2 Техническая дирекция указана в вопросе сотрудника до описания изменившихся условий. Опубликованные результаты фиксируют финальные ошибки, точные планы восстановления из исходных прогонов пока недоступны.

Для продолжения после полной инструкции восстановитель получает исходный вопрос и ранее разрешённую тему. Текст инструкции сохраняется в его входе при явной ссылке на ответ или конкретный шаг. Если восстановитель связал ход с такой темой, но пропустил единственную известную дирекцию, код возвращает её в поисковый вопрос. Уточнения бота остаются частью доступной истории.

На локальных проверках совпали маршруты и хеши запросов к моделям для 10 первых инструкций и 50 одиночных вопросов при одинаковых тестовых ответах моделей. Офлайн-результат проверки поиска для 42 ходов совпал с результатом исходного коммита. MiniLM вернул IB §4.3 и TECH §16.4 в первой пятёрке для вручную восстановленных вопросов о площадке и начале работ. Тесты ядра опровергают зависимость входа восстановителя от разных формулировок полной инструкции и проверяют возврат пропущенной дирекции. Сквозные серии остановились при первом сетевом обращении к OpenRouter. Итоговая оценка кандидата остаётся открытой.

Для повторной проверки нужны фактические первые ответы из базового `replies.jsonl` и `validation.json` варианта C на исходном коммите. Сравнение подставляет один и тот же второй вопрос в обе истории и записывает восстановленный запрос, дирекцию, выдачу, пункты генератора, вердикт и видимый ответ. После этого две полные серии используют собственную историю каждого сценария.

```sh
python3 eval/conversations/reasoning_trial.py \
  --compare-histories "$BASE_REPLIES" "$VARIANT_C_REPLIES" --case P03 --case P10 \
  --model-dir "$MINILM_DIR" --python "$RERANK_PYTHON" --out "$CROSS_OUT"
python3 eval/conversations/reasoning_trial.py --winner C \
  --model-dir "$MINILM_DIR" --python "$RERANK_PYTHON" --out "$COMPLEX_OUT"
python3 eval/conversations/reasoning_trial.py --winner C --working50 "$WORKING_ZIP" \
  --model-dir "$MINILM_DIR" --python "$RERANK_PYTHON" --out "$WORKING_OUT"
```

Оценка по оригиналам должна подтвердить P03.2 и P10.2, сохранение P03.1, P08.1 и P09.1 и прежние результаты по остальным репликам. Трассы и рабочий пакет остаются в закрытом окружении.
