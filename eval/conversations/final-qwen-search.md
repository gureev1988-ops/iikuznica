# F3. Qwen 122B с одним поисковым раундом

Контроль — A1 на `1cf4496` с теми же MiniLM, генераторами и Decider. Сравниваются A1, Qwen без reasoning на фиксированной выдаче A1 и та же Qwen с одним прямым запросом к локальному поиску. Дополнительный маршрут включается после уточнения или эскалации при единственной известной дирекции и доступной трассе поиска. Явный блок A1 и запрос недостающего обстоятельства проекта сохраняются. В обеих ветвях Qwen одинаковый предел чтения оригиналов. В ветви поиска можно добавить до четырёх пунктов в пределах этого бюджета. Новый ответ проходит Decider и A1.

Панель содержит десять рабочих сценариев и пять новых трудных реплик. Сравниваются только парные ответы с собственной историей каждой ветви. `F3-eligible` показывает охват. `F3-search` и `F3-sources` показывают добавленные пункты и объём чтения. Один раунд поиска добавляет до двух обращений к Qwen на подходящую реплику.

## Запуск в Codex Cloud

Перейди на ветку эксперимента. Для живого запуска нужны прежняя среда с `OPENROUTER_API_KEY`, закреплённый MiniLM и зависимости поиска из PR #26.

```sh
D=/workspace/scratch/answer-quality-pr26
T=eval/conversations/final_search.py
python3 "$T" --check
python3 "$T" --model-dir "$D/minilm" --python "$D/venv/bin/python" \
  --out "$D/final-experiments/qwen-panel"
```

После успешной панели тот же скрипт запускает парную проверку на рабочих 42 ходах или 50 вопросах. Для каждого запуска укажи новый `--out`. Для рабочего контроля на 42+50 достаточно один раз выполнить эти команды с `--arm control` в любой из трёх веток.

```sh
python3 "$T" --suite working42 --model-dir "$D/minilm" --python "$D/venv/bin/python" \
  --out "$D/final-experiments/qwen-42"
python3 "$T" --suite working50 --working50 "$WORKING_ZIP" \
  --model-dir "$D/minilm" --python "$D/venv/bin/python" --out "$D/final-experiments/qwen-50"
```

`WORKING_ZIP` указывает на оригинальный `IIkuznitsa_Final15.zip`. `--reuse` принимает каталог прежних точных модельных вызовов. По умолчанию парный кандидат переиспользует запросы, полностью совпавшие с контролем. Для замера холодного времени используй новый каталог, `--independent-calls` и прежние параметры моделей.

## Как оценивать

У варианта с поиском должно появиться минимум два дополнительных пригодных ответа относительно обоих контролей при нуле новых ошибочных инструкций. Если выигрывает только Qwen на фиксированных пунктах, польза дополнительного поиска остаётся неподтверждённой. Сравнить частоту вызовов, стоимость и p95. Если подходящих реплик мало, записать низкий охват отдельно.

Сводка `summary.json` содержит действия, вызовы, стоимость, задержки и события маршрута. Оценка содержания по оригиналам проводится по `pairs.json`. Синтетические примеры и рабочие истории оцениваются отдельно. На рабочем корпусе кандидат должен сохранить 50/50, точечные 5/5 и не добавлять ошибочных инструкций. Два контрольных дефектных черновика должны остаться удержанными.

В Git публикуются код, рабочие тесты и агрегаты. Сырые трассы остаются в окружении. Blind20 используется после заморозки финальных кандидатов.
