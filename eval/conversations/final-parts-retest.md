# F1b. Проверка частичного ответа с заданным и автоматическим разбором

В первом F1 все три попытки разметить составной запрос остановились до обработки частей. На той же рабочей панели из 18 ходов F1b разделяет проверку гипотезы и проверку автоматизации. Поиск, восстановление истории, генератор, Decider и допуск A1 остаются прежними.

| Вариант | Что меняется |
|---|---|
| `control` | Штатный ответ A1. |
| `oracle` | После общего отказа или уточнения использует зафиксированные границы просьб на шести открытых примерах F1. Границы содержат исходные слова, область и зависимости. На каждый рабочий запрос отвечает штатное ядро. |
| `auto` | Код предлагает один или несколько разборов из дословных частей запроса. Модель возвращает только номер варианта или ноль. Код проверяет область, покрытие текста и личную просьбу без дирекции. При выраженной зависимости автоматический разбор сохраняет ответ A1. |

Обе ветви берут результат только когда хотя бы одна часть получила подтверждённый ответ. При размеченной зависимости следующую часть удерживают до уточнения предпосылки. Разметка `oracle` доступна только для рабочей панели. Blind20 не входит в этот запуск.

## Запуск

```sh
D=/workspace/scratch/answer-quality-pr26
T=eval/conversations/final_parts_retest.py
python3 "$T" --check
python3 "$T" --model-dir "$D/minilm" --python "$D/venv/bin/python" \
  --out "$D/final-experiments/parts-retest"
```

Если доступен каталог исходного F1, добавь к живой команде `--reuse "$D/final-experiments/parts-panel/control"`. Это сохраняет ответы A1 для полностью совпадающих модельных запросов. Для отдельного замера времени без кеша используется новый каталог и `--independent-calls`.

## Как читать результат

1. Сравнить `oracle` с `control` на F1-01–F1-03. Гипотеза получает поддержку на панели, если как минимум в двух репликах вернулся подтверждённый ответ, а спорная часть получила уместное отдельное действие. Непрофильное не направляется в качество. Сверить каждую опубликованную инструкцию с оригиналом.
2. Сравнить `auto` с `oracle`. Если эффект есть только с заданными границами, работа над автоматическим разбором остаётся открытой. Если и заданный разбор не дал результата, смотреть на этап обработки частей или завершить опыт без принятия гипотезы.
3. Проверить, что оба кандидата не вводят ошибочных инструкций, P01–P03 сохраняют контрольные действия, а F1-05 и F1-06 не выдают безусловную инструкцию при неизвестной предпосылке. При появлении кандидата для интеграции отдельно перепроверить `--arm auto --suite working42` и `--arm auto --suite working50` на оригинальном банке.

`summary.json` показывает вызовы и сколько раз дошли до обработки частей. `pairs.json` содержит видимые результаты. События `F1b-oracle-executed` и `F1b-auto-executed` в `rows.json` показывают действия по каждой просьбе, в том числе попытки, после которых итоговая реплика сохранилась. Код и агрегат публикуются в PR #30. Модельные трассы остаются в окружении.
